# Тестовый план СМП

---

## 1. Область и подход

**Область:**

    - ядро — Authorization и Card Management;

    - периферия — Gateway, Switch, симуляторы, Transaction Logger, Web Dashboard. Детализация области и обоснование исключений — в [`test-strategy.md`](test-strategy.md).

**Подход:** чёрный ящик; классы эквивалентности, граничные значения, попарное тестирование (PICT); риск-ориентированный приоритет.

**Критерии входа:**

- `docker compose up -d` поднимает все 11 сервисов + PostgreSQL + RabbitMQ без ошибок
- Все health-check'и возвращают 200
- Сгенерировано ≥ 100 тестовых карт через `POST /api/cards/generate`
- ТЗ 04 и 05 согласованы, тестовые данные подготовлены

**Критерии выхода:**

- Все тест-кейсы из [`test-design.md`](test-design.md) выполнены
- Нет открытых дефектов критического и высокого уровня
- Покрыты все классы эквивалентности и границы (≥ 95 % ключевых полей)
- Оба попарных набора PICT спроецированы в тест-кейсы

**Критерии приостановки и возобновления:**

- **Приостановка:** блокирующий дефект критического уровня (например, `docker compose up` не работает)
- **Возобновление:** дефект устранён, окружение восстановлено

## 2. Ресурсы

- **Ресурсы:** 2 тестировщика, окружение dev
- **Метрики:** доля выполненных тест-кейсов, число открытых дефектов по уровням

**Инструменты и окружение:**

| Компонент        | Чем работаем                     | Назначение                        |
| ---------------- | -------------------------------- | --------------------------------- |
| Язык и фреймворк | Java 21, Spring Boot 3, Maven    | бэкенд-сервисы СМП                |
| Фронтенд         | Node, React, TypeScript, Vite    | Web Dashboard                     |
| БД и брокер      | PostgreSQL, RabbitMQ             | карты, лимиты, очередь транзакций |
| Запуск стенда    | Docker Desktop, `docker compose` | поднять весь стенд одной командой |
| Тест-дизайн      | PICT (2-wise)                    | `pict/model.txt` → `cases.txt`    |
| Проверка API     | `curl`, `jq`                     | ручные прогоны и разбор ответов   |
| CI               | GitHub Actions                   | quality gates                     |

## 3. Риски

|    №    | Описание риска                                                                   | Вероятность | Влияние | Стратегия митигации                                                                                                          |
| :-----: | :------------------------------------------------------------------------------- | :---------: | :-----: | :--------------------------------------------------------------------------------------------------------------------------- |
| **R-1** | Изменение формата/схемы DTO запроса авторизации со стороны смежных команд        |   Средняя   | Высокое | Фиксация контрактов в ТЗ до начала написания тестов; версионирование API.                                                    |
| **R-2** | Нестабильность работы RabbitMQ при асинхронном логировании                       |   Низкая    | Среднее | Тестирование изоляции: проверка, что недоступность очереди не блокирует синхронный ответ авторизации (eventual consistency). |
| **R-3** | Состояние гонки (Race Condition) при параллельном списании средств с одной карты |   Средняя   | Высокое | Добавление в план проверок стресс-тестов на параллельные запросы с одним PAN.                                                |
| **R-4** | Срыв сроков сдачи из-за блокирующего бага в `docker-compose`                     |   Низкая    | Высокое | Ежедневный запуск smoke-тестов на чистом окружении перед началом тестовых сессий.                                            |
